# نظام الصيدلية — Pharmacy POS

نظام مبيعات ومخزون للصيدليات، يعمل على ويندوز دون إنترنت.
الإصدار الحالي 0.1: شاشة البيع، والدفعات، والصرف بقاعدة FEFO، وقارئ باركود GS1، وقاعدة بيانات محلية مع سجل تدقيق.

## التجربة

- **ملف التثبيت:** من تبويب **Actions** في GitHub افتح آخر تشغيل ناجح لـ CI، ثم نزّل `PharmacyPOS-windows-installer` من قسم Artifacts.
- يبدأ البرنامج ومعه بيانات تجريبية: ١٢ صنفاً، بعض دفعاتها قريبة الانتهاء ودفعة منتهية. الهدف أن ترى التنبيهات وقاعدة FEFO فعلياً.
- **أول تشغيل:** يطلب البرنامج اختيار كلمة مرور لحساب المدير `admin` (٨ أحرف على الأقل)، ثم يُطلب تسجيل الدخول في كل مرة.
- **في المتصفح** (`npm run dev`): المستخدمون `admin` و`pharm` و`cash` وكلمة المرور `demo1234`.
- باركودات للتجربة: `2000000000046` (Panadol Extra)، `2000000000015` (Glucophage 850)، أو نص GS1 مثل `(01)02000000000077(17)301231(10)B2311`.

## قارئ الموبايل
أي موبايل على شبكة الواي فاي نفسها يعمل قارئ باركود مجاناً:
1. في شاشة البيع اضغط **قارئ الموبايل** وامسح رمز QR بكاميرا الموبايل.
2. في أول مرة يظهر تحذير «الاتصال ليس خاصاً» لأن الشهادة صادرة عن البرنامج نفسه: **متقدم ← متابعة**. (المتصفح لا يسمح بالكاميرا إلا عبر https.)
3. اسمح بالكاميرا ووجّهها إلى الباركود؛ يُضاف الصنف إلى الفاتورة مباشرة. باركود GS1 DataMatrix ينقل رقم التشغيلة والانتهاء أيضاً.

البرنامج يستقبل على المنفذ 8080 (https). الرابط يحمل رمز اقتران جديداً عند كل تشغيل، فلا يستطيع غيره على الشبكة إرسال أصناف. إن سأل Windows عن السماح بالوصول للشبكة فاختر «الشبكات الخاصة». المكتبة html5-qrcode (Apache-2.0) مضمّنة في البرنامج، فلا حاجة للإنترنت.

## طباعة الفاتورة
- بعد إتمام البيع اضغط **طبع الفاتورة**، أو فعّل «طباعة الفاتورة تلقائياً بعد البيع» في لوحة الدفع (يُحفظ لكل جهاز).
- **فواتير اليوم** تعرض فواتير اليوم مع معاينة الإيصال وإعادة طباعته؛ النسخة المعادة تُطبع عليها كلمة «نسخة» وتُسجَّل في سجل التدقيق. الكاشير يرى فواتيره فقط.
- المدير يحدد اسم الصيدلية والعنوان والهاتف ورسالة أسفل الإيصال ومقاس الورق (حراري 80 أو 58 مم، أو A4) من **بيانات الإيصال**.
- الإيصال يُبنى من الفاتورة المحفوظة، وطوله يُضبط على محتواه فلا تُهدر الطابعة الحرارية ورقاً. في أسفله باركود رقم الفاتورة (Code 128).
- عند أول طباعة اختر الطابعة الحرارية ومقاس الورق في نافذة الطباعة.

## المزامنة السحابية (Supabase)

البرنامج يعمل دائماً على قاعدة البيانات المحلية، بإنترنت أو بدونه. المزامنة اختيارية وتربط أكثر من جهاز في الصيدلية نفسها:

1. في مشروع Supabase افتح **SQL Editor** وشغّل الملف `supabase/schema.sql` كاملاً، ثم سجّل كلمة سر المزامنة بالأمر المكتوب في أول الملف.
2. في البرنامج: **الموظفين ← المزامنة السحابية**، أدخل عنوان المشروع والمفتاح العام (anon key) وكلمة سر المزامنة، وفعّل المزامنة. كرّر ذلك على كل جهاز.

- **ما يُرسَل:** كل بيع وفاتورة شراء واستلام وتصحيح جرد وتعديل صنف وسطر في سجل التدقيق يُحفظ في جدول `sync_queue` في المعاملة نفسها، ثم يُرسل بالترتيب عند توفر الاتصال. إعادة الإرسال بعد انقطاع لا تكرّر شيئاً.
- **ما يُستلَم:** كتالوج الأصناف والأسعار (السحابة هي المرجع: آخر تعديل يصل يُعتمد) ومخزون كل دفعة = مجموع حركات كل الأجهزة، مضافاً إليه ما لم يُرسل بعد من هذا الجهاز. الموظفون والموردون يبقون محليين.
- **الشارة أعلى الشاشة:** أخضر «متصل · تم المزامنة»، أصفر «جاري المزامنة...»، أحمر «غير متصل · يعمل محلياً»، برتقالي «تعذّرت المزامنة» (مفتاح أو كلمة سر خاطئة، أو عملية رفضها الخادم؛ التفاصيل عند المرور على الشارة)، رمادي إن لم تُفعّل.
- **الأمان:** الجداول في مخطط `pos` غير المكشوف، ولا يصل إليها الجهاز إلا عبر دالتي `pos_sync_push` و`pos_sync_pull` مع كلمة سر المزامنة. المفتاح وكلمة السر لا يُعرضان في الشاشة بعد حفظهما ولا يُكتبان في سجل التدقيق.
- **اختبار على مشروع حقيقي:** `POS_SYNC_URL=… POS_SYNC_KEY=… POS_SYNC_SECRET=… cargo test --lib -- --ignored two_tills` (على مشروع فارغ).

## التطوير

```bash
npm install
npm test            # اختبارات المنطق: FEFO، GS1، الحسابات
npm run dev         # الواجهة في المتصفح ببيانات تجريبية في الذاكرة
npm run tauri dev   # التطبيق الكامل على سطح المكتب (يحتاج Rust)
cargo test --manifest-path src-tauri/Cargo.toml   # اختبارات قاعدة البيانات
```

| المجلد | المحتوى |
|---|---|
| `src/core` | منطق نقي مع اختبارات: FEFO، تحليل GS1، الفاتورة والدفع |
| `src/data` | طبقة البيانات: SQLite داخل التطبيق، وذاكرة مؤقتة في المتصفح |
| `src/pos` | شاشة نقطة البيع وفواتير اليوم |
| `src/components` | الإيصال (`ReceiptPrint`) ومضيف الطباعة (`PrintHost`)؛ قواعد الطباعة في `src/styles/print.css` |
| `src-tauri/src/phone_scanner.rs` | خادم قارئ الموبايل (https على 8080) وصفحة المسح `assets/scan.html` |
| `src/inventory` | شاشة المخزون: البحث والتصفية، إضافة صنف، استلام دفعة، تعديل الكمية بعد الجرد |
| `src/purchasing` | شاشة المشتريات: فاتورة المورد، مسح باركود GS1، أسعار الشراء والبيع، الترحيل |
| `src/reports` | التقارير: المبيعات والأرباح، الصلاحية والتالف، إعادة الطلب، سجل الوصفات، سجل التدقيق؛ مع الطباعة وتصدير CSV |
| `src/users` | الموظفين (للمدير فقط): إضافة موظف، الدور، استثناءات الصلاحيات، التعطيل، إعادة كلمة المرور |
| `src/core/permissions.ts` | الأدوار وصلاحياتها الافتراضية (نفس جدول `role_default` في الخادم) |
| `src/auth` | شاشة تسجيل الدخول وإعداد كلمة مرور المدير |
| `src-tauri/src/lib.rs` | قاعدة البيانات: البحث، والبيع داخل معاملة واحدة، وأوامر المخزون والمشتريات والتقارير والموظفين، وتسجيل الدخول، وسجل التدقيق |
| `src-tauri/src/sync.rs` | المزامنة السحابية: قائمة الانتظار، الإرسال والاستلام، العامل في الخلفية |
| `src-tauri/migrations` | مخطط الجداول والبيانات التجريبية |
| `supabase/schema.sql` | الجانب السحابي: الجداول ودالتا المزامنة في Supabase |
| `templates/import-template.xlsx` | قالب Excel لإدخال الأدوية والموردين والمخزون الافتتاحي |

## مبادئ ثابتة
- **الرصيد يُحسب من الحركات:** كل بيع أو شراء أو إتلاف يُسجَّل حركة على دفعة محددة.
- **لا بيع لدفعة منتهية:** القاعدة تتحقق من ذلك داخل المعاملة نفسها.
- **سجل التدقيق للإلحاق فقط:** لا يُعدَّل ولا يُحذف، وكل سطر يحمل بصمة السطر الذي قبله.
- **قاعدة البيانات هي المرجع في البيع:** يُرفض البيع إذا اختلف السعر عن سعر الصنف المسجّل، أو كان الخصم سالباً أو أكبر من قيمة السطر.
- **سقف الخصم:** مجموع الخصومات لا يتجاوز `max_discount_pct` من جدول `settings` (الافتراضي ١٠٪)، ما عدا المدير والصيدلاني المسؤول.
- **أدوية الوصفة:** لا يصرفها إلا صيدلاني أو صيدلاني مسؤول أو مدير، مع رقم الوصفة واسم الطبيب، وتُحفظ في `sale_prescriptions`.
- **البائع هو المستخدم المسجّل دخوله:** تأخذه الواجهة الخلفية من الجلسة، لا من الشاشة.
- **الصلاحيات من قاعدة البيانات:** لكل دور صلاحيات افتراضية (إعطاء خصم، صرف أدوية الوصفة، عرض التقارير، تعديل المخزون)، ويمكن للمدير منح صلاحية أو منعها لموظف بعينه. الخادم يتحقق منها مع كل أمر، فتعطيل حساب أو سحب صلاحية يسري فوراً. إدارة الموظفين للمدير فقط، ولا يمكنه تعطيل حسابه أو إزالة دور المدير عن نفسه. كلمات المرور مشفّرة بـ Argon2 ولا تُكتب في سجل التدقيق.
- **تعديل المخزون:** للمدير والصيدلاني وأمين المخزن فقط. الاستلام يُنشئ دفعة جديدة وحركة `purchase`، والتصحيح بعد الجرد يتطلب سبباً ويُسجَّل حركة `adjust` بالفرق، وكلاهما في سجل التدقيق.
- **فاتورة الشراء تُرحَّل دفعة واحدة:** الفاتورة وأسطرها والدفعات وحركات `purchase` وحساب المورد وسجل التدقيق في معاملة واحدة؛ أي خطأ في سطر يلغي الفاتورة كلها. التشغيلة الموجودة تُضاف كميتها بمتوسط كلفة مرجّح، وسعر البيع في الفاتورة يصبح سعر الصنف. المخزون متاح للبيع فوراً بقاعدة FEFO.
- **التقارير:** المبيعات والأرباح وسجل الوصفات للمدير والصيدلاني المسؤول فقط؛ تقارير الصلاحية وإعادة الطلب لمن يدير المخزون. الربح = صافي المبيعات − كلفة الدفعات المباعة، وخصم الفاتورة يُوزَّع على أسطرها بالقيمة. ملف CSV يُحفظ في مجلد التنزيلات. الأسبوع في فترة «هذا الأسبوع» يبدأ يوم السبت. التواريخ تُحوَّل مرة واحدة إلى حدود UTC فتستخدم الاستعلامات الفهارس بدل فحص كل الصفوف.
- **سجل التدقيق:** للمدير فقط، ضمن التقارير. يُسجَّل كل تغيير مع المستخدم (الاسم واسم الدخول) والوقت، وما قبل التغيير وما بعده: إضافة الأصناف وتعديل بياناتها، تغيير سعر البيع (يدوياً أو من فاتورة شراء)، استلام الدفعات مع الكمية وتكلفة الوحدة قبل وبعد، تصحيح الجرد، الموظفين وأدوارهم وصلاحياتهم وتفعيل حساباتهم وكلمات المرور (دون تسجيل كلمة المرور نفسها)، حد الخصم وإعدادات الإيصال، وتسجيل الدخول والبيع وإعادة الطباعة. فلاتر سريعة: تعديلات المخزون، إدارة المستخدمين، تغيير الأسعار، تسجيل الدخول، المبيعات، الإعدادات؛ وزر «عرض» يفتح العملية كاملة: كل حقل تغيّر بقيمته السابقة والجديدة، والبيانات كما خُزّنت مع بصمتها. عند كل عرض يُعاد حساب سلسلة البصمات (SHA-256) للسجل كاملاً، فيظهر «تم العبث به» مع رقم أول عملية لا تطابق إن عُدّل السجل خارج البرنامج.
- **تعديل الأصناف وحد الخصم:** من نافذة الصنف في المخزون يمكن لمن يدير المخزون تعديل بياناته وسعر بيعه. حد الخصم (للصيدلاني والكاشير) يغيّره المدير من شاشة الموظفين.
